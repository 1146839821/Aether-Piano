# 08｜C++ 实时音频工程规范与可重复构建

## 定义严格的 RT Contract

在 `PianoEngine::process` / JUCE `processBlock` 的音频线程中：

- 不允许 `new/delete`、`malloc/free`、容器扩容、字符串格式化、动态异常、同步日志、文件读写、网络或阻塞锁。
- 不允许等待 UI/worker 完成；跨线程传参数必须有明确内存可见性、生命周期和非阻塞机制。
- 所有 per-voice、字符串状态、音板状态、过采样缓冲、卷积缓存及事件缓存在 `prepare()` 或 worker 侧预分配。
- 处理输入样本为 0、空 MIDI、任意 `numSamples≤maxBlockSize`、宿主变更采样率、Reset、多次初始化的条件。
- 通过 RT 内存分配探针和压力测试证明约束；仅仅“代码看起来无 new”不够。

## 标准工具链

```bash
# 仅示例：实际分支/tag/commit 必须 P00 验证并固定
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug --parallel
ctest --test-dir build/debug --output-on-failure

cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release --parallel
ctest --test-dir build/release --output-on-failure
```

多配置生成器（MSVC/Xcode）使用 `--config Debug/Release`；单配置生成器使用 `CMAKE_BUILD_TYPE`。由 P00 将这两种情况写成跨平台 README。

## 依赖治理

- JUCE：Git submodule 锁定可验证的 9.x tag/commit，记录 `git rev-parse HEAD`；库的实际 license 模式由工程负责人决定。
- GoogleTest/Catch2 等：需审核许可证与许可证文件；并非必须，首版可用最简单的测试框架。
- Python：`requirements.txt` 或 lockfile；版本、平台、模型参考脚本可重建。
- 任何新依赖须填写 license/版本/SBOM 条目及构建目的。

## 测试与编译选项

- Debug：`-Wall -Wextra -Wpedantic` 或 MSVC 对应检查；在支持系统使用 ASan/UBSan，注意不能用带 sanitizer 的结果衡量最终实时性能。
- Release：相同声学参数和测试信号下可重现；不能依赖不稳定的快速数学优化而改变基频或损耗。
- 对 `denormal`、SIMD、浮点舍入与向量化采用明确策略，保留标量正确性参考实现。
- 频繁迭代采用 golden **特征范围**而不是原始 PCM 位级比较（浮点、平台与编译器可能导致微小差异）；有确定性约束的同机回归例外。

## 性能记录

每次引入琴弦、桥口、音板、踏板功能都跑 48k/64、128 下的 stress suite。统计 p50/p95/p99/max；Profiler 的样本包含宿主/系统干扰，记录测试设备、声学模型版本和 OS 状态。

## 代码审查规则

1. 新增实时模块需附音频线程内存/锁行为说明。
2. 新增物理模块需写明状态变量、单位、能量流、离散方法、测试案例和已知近似。
3. 数学滤波器需测稳定域、频响、群延迟，极点/系数更新不得产生不连续爆音。
4. 参数改动需更新 schema 版本和迁移代码。
5. 声音调整需保存 baseline.wav、candidate.wav、分析结果和版本信息。
6. 影响许可证或发行资源的修改必须人工审核。

## 最小 CI 闸门

- Windows：CMake Configure + Debug/Release + unit/asset schema + 静态测试。
- macOS：相同任务 + AU 构建（具备 macOS runner 时）。
- Linux：可作为 DSP/离线测试 runner；GUI 或 JUCE 系统依赖因平台而异。
- 真实 DAW 和硬件回调时序需人工/专门 CI；云 runner 不等于音乐制作机器的 RT 结果。

## ADR / 实验追踪

每当改动 `waveguide` vs `modal`、桥口耦合、语义事件或 RT 快照交换方案，用 `templates/ADR_TEMPLATE.md` 创建决策记录。失败实验不要删除；状态写 `rejected` 或 `superseded`。
