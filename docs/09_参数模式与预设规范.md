# 09｜每键物理参数、数据版本与预设规范

## 目标：参数有单位、出处和可迁移 schema

`grand_v1.json` 不是一张凭空填满的数字表，而是 88 个音符可独立设置或插值的物理模型配置。每个字段应记录单位、估计方法、来源、有效范围和采样率依赖关系。

## 关键字段

| 区域 | 字段 | 单位或意义 | 来源状态 |
|---|---|---|---|
| Tuning | `f0_hz` | 目标频率 Hz | measured / fitted / estimated |
| String | `string_count` | 1–3 根，整数 | physical specification |
| String | `length_m`, `tension_N`, `linear_density_kg_m` | 实际弦参数 | measured / literature / fitted |
| String | `inharmonicity_B` | 无量纲 | measured/fitted |
| String | `strike_position_ratio` | 弦长比例 | measurement / estimated |
| String | `partial_decay_t60_s` | 多个泛音的 T60 秒 | measured/fitted |
| Unison | `detune_cents` | 同键各弦失谐 | fitted |
| Hammer | `mass_kg`, `stiffness_K`, `contact_exponent` | 质量、非线性刚度、指数 | measured/fitted |
| Hammer | `velocity_curve` | MIDI→m/s 的有界映射 | calibrated |
| Damper | `contact_ratio`, `damping_strength` | 接触位置与损耗系数 | measured/fitted |
| Bridge | `bridge_group_id` | 多弦共用阻抗组 | model |
| Soundboard | `modal_bank_ref` | 对应音板模态参数引用 | fitted |
| Metadata | `calibration_status`, `source_ref`, `confidence` | 出处与可信度 | required |

## 数据文件草案（非真实钢琴参数）

```json
{
  "schema_version": 1,
  "model_id": "grand_research_v1",
  "reference_a4_hz": 440.0,
  "model_status": "unmeasured_prototype",
  "notes": {
    "60": {
      "label": "C4",
      "string_count": 3,
      "f0_hz": 261.625565,
      "inharmonicity_B": null,
      "strike_position_ratio": null,
      "hammer": {
        "mass_kg": null,
        "stiffness_K": null,
        "contact_exponent": null
      },
      "unison_detune_cents": null,
      "partial_decay_t60_s": null,
      "calibration_status": "UNMEASURED",
      "source_ref": null
    }
  }
}
```

**特别提醒：** 这里的 `string_count: 3` 仅为中音 C4 示例配置，不代表任何特定型号钢琴的真实测量。所有 `null` 表示未标定；不能默默补随机值。引擎可以在 `debug_prototype` 模式使用单独的显式默认值文件，但应阻止错误声明“实测型号”。

## 实时参数与非实时参数

- `FastAudioParameters`：音量、踏板、演奏灵敏度和小幅调音等可安全平滑的值。
- `ModelParameters`：音板模态数、弦数量、滤波拓扑、分数延时缓存尺寸等**结构性**参数只能在 worker 构建，音频线程安全地在边界切换或要求停止音频。
- 预设 JSON 的读取、解析、验证和迁移在非 RT 线程完成；DSP 核心只看到经过校验和预计算的 POD/只读快照。

## 标准化与兼容

- `schema_version` 为正整数；迁移函数 `upgrade(v1→v2)` 有单元测试。
- 物理参数版本和用户预设版本分离：UI 改动不会让物理模型编号自动变更。
- 序列化保持确定性排序；保存宿主状态后重新加载，可重现音色。采样率和宿主名称不应写死成必要前提。
- 不把原始未授权参考录音嵌入模型数据或安装包。

## 标定轨迹

每音记录 `source_recording_id`、`fit_version`、`algorithm_version`、`loss`、`validation_loss`、`date`、`license_notes`。插值结果使用 `estimated_from_neighbors` 标识，绝不以插值值假装每音实测。
