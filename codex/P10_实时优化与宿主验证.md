# P10｜CPU 优化、跨平台、插件验证与高负载测试 — Codex 可执行任务

> **开始条件：** P09 插件 GUI/状态可用，核心模型声学对照已建立。。这是完整的执行任务，不是仅供讨论的需求草案。

## 本阶段唯一目标

在明示的测试硬件和 DAW 场景中证实插件的实时安全性、性能稳定与跨宿主兼容，优化时不牺牲已验证的声学行为。

## 必须实现的事项

1. 建立固定 MIDI 压测序列：独奏、32/64 复音、踏板共鸣重负载、极短块 64、可变块/采样率 44.1k/48k/96k。
2. 使用 release profiler 定位高 CPU 目标：琴弦更新/散射、共鸣调度、音板模态、过采样与辐射；优先算法和缓存改进，最后考虑 SIMD/线程架构。
3. 如采用 voice culling 或降低共鸣模态，必须导出听音与特征 A/B，记录 CPU 收益与声学误差。
4. 使用专门 instrumentation 测 RT 动态分配/析构、锁等待、文件系统调用；所有 callback 相关路径包含参数交换、预设/GUI 改动。
5. 实际运行 Steinberg VST3 Validator 和 pluginval；再针对有安装条件的 Windows/macOS DAW 验证加载/卸载、状态保存、离线渲染、自动化、菜单和采样率切换。
6. 设计异常/fuzz 参数、错误预设、事件洪泛、64/128 样本块长跑测试；记录崩溃、dropouts、NaN 和 CPU。
7. 编写目标系统/架构/DAW 支持矩阵。未跑过的系统填 NOT RUN，不得用推测补完。

## 实际测试与复现

- 每套性能结果包含 CPU/OS/电源模式/编译器/commit/模型版本/采样率/块大小/复音/踏板/统计窗口。
- 报告 p50/p95/p99/max 和 DAW 掉音；对 48k/64 的 1.333ms 期限设计余量（如初步 70% 工程预算），但不得脱离指定硬件宣称“永不爆音”。
- 参数 fuzz、状态迁移、跨采样率与验证工具真实运行并保存机器日志；保留全部失败项与修复回归。
- 对优化前后声学特征进行一致性比较，且由人进行听音检查。

## 交付文件

profiler 与回归脚本、性能矩阵、pluginval/Validator 日志、宿主支持表、RT allocation 报告、`experiments/P10/PHASE_REPORT.md`。

1. 在开始改动前读取根目录 `AGENTS.md`、`README.md`、`docs/06_阶段路线图与验收门.md`、本阶段指定的文档与前阶段实际 `PHASE_REPORT`。
2. 检查 `git status`；不要覆盖未知或未提交的用户更改。提出短计划后实际编辑代码/文档。
3. 明确真实运行过的命令与结果（PASS / FAIL / SKIP / NOT RUN）。失败不得消失；禁止伪造音频、图表、编译日志或 CPU 数据。
