# P11｜发布候选、许可与可复现发行包 — Codex 可执行任务

> **开始条件：** P10 目标宿主/平台验证通过；已有明确的商业许可及第三方资源审查结论。。这是完整的执行任务，不是仅供讨论的需求草案。

## 本阶段唯一目标

生成可复现的 Release Candidate (RC) 和完整可验证的发行资料；对外质量描述以实际测试证据为依据。

## 必须实现的事项

1. 审计第三方源码、JUCE 许可策略、素材来源、音板参数参考、商标与示例录音使用权；形成 SBOM / attribution / license decisions。没有授权时 BLOCKED，不能替开发者接受许可证。
2. 编写 `RELEASE_CHECKLIST.md`、系统需求、目标 DAW 兼容清单、用户手册、已知限制、错误反馈和恢复方法。
3. 配置 Windows 与 macOS 的安装包构建。签名、公证、证书和账户操作只在已获授权环境进行；任何密钥都不能直接写在仓库文件。
4. 锁定 JUCE/第三方依赖、模型数据版本和编译选项；记录构建环境与文件 SHA256，可根据 tag 重建。
5. 创建 `0.9.0-rcN` 的候选标签，但不要直接发布正式 `1.0.0`，除非人工验收全部完成。
6. 回归执行 P02–P10 关键音频、性能和宿主测试；在目标 OS 上安装、加载、关闭/卸载。做最终盲听/演奏检查并记录签名者。
7. 生成可再现的 release notes、变更摘要、许可证清单、用户文档和阻断问题清单。

## 实际测试与复现

- Release 构建/全部 CTest/声学回归/插件 Validator 和指定 DAW 的真实测试报告归档。
- 检查安装包和模型数据文件 SHA256、签名/公证状态（适用时）以及受支持平台能否安装和移除。
- 声明 P08 高级功能/音质对标的真实状态，不以“Pianoteq 级别”作未经听测证实的保证。
- 缺许可、未执行宿主 QA、仍有已知能导致崩溃的问题时，只能输出候选阻断报告，不得宣称可销售。

## 交付文件

RC 构建脚本/安装包（有权限和环境时）、checksums、SBOM、LICENSE 账本、用户手册、发行说明、`experiments/P11/PHASE_REPORT.md`。

## 质量门 / 不允许的捷径

通过：合法授权、可复现构建、实际宿主/安装测试、没有 RC 阻断项及明确的人工签发；否则结论 BLOCKED。

## 统一执行协议（每阶段必做）

1. 在开始改动前读取根目录 `AGENTS.md`、`README.md`、`docs/06_阶段路线图与验收门.md`、本阶段指定的文档与前阶段实际 `PHASE_REPORT`。
2. 检查 `git status`；不要覆盖未知或未提交的用户更改。提出短计划后实际编辑代码/文档。
3. 明确真实运行过的命令与结果（PASS / FAIL / SKIP / NOT RUN）。失败不得消失；禁止伪造音频、图表、编译日志或 CPU 数据。
4. 将输出写入 `experiments/P11/`，至少包含 `PHASE_REPORT.md`，实际测试日志及物理声学结果；无音频结果时解释原因。
5. 保持插件 `processBlock` 与 DSP `process` 无动态分配、锁等待、文件/网络 IO 和同步日志；保留最小回滚路径。
6. 完成后给出更改文件、复现命令、测试状态、定量结果、已知近似、风险及阶段门结论；如不满足，则标为 `BLOCKED` 并停止，而非直接执行下一阶段。
