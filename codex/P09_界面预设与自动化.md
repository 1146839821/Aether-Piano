# P09｜演奏 GUI、物理参数、预设和宿主状态 — Codex 可执行任务

> **开始条件：** P06 的基础乐器可靠；P07 的参数格式可读，P08 可选。。这是完整的执行任务，不是仅供讨论的需求草案。

## 本阶段唯一目标

开发“可弹、可调、可保存”的原创插件体验，不让 GUI 破坏已验证的实时音频线程契约。

## 必须实现的事项

1. 使用 JUCE 构建原创 GUI：Performance、Hammer、Strings、Bridge & Resonance、Soundboard、Output；使用非商用/原创设计资源。
2. 借助 APVTS 或明确的等价宿主参数管理机制，对参数进行 ID/范围/默认值/单位/自动化标注；参数分为 RT 快速可平滑与结构需重建两类。
3. UI 与 DSP 独立；结构参数只在 worker 建立经校验的状态快照，再通过安全的无阻塞生命周期方案切换，不可在 audio callback 释放旧状态。
4. 实现预设浏览/加载/保存、宿主 `getStateInformation`/`setStateInformation`、schema 迁移、默认预设、安全回退与错误处理；文件读写不得发生在音频回调中。
5. 加入 MIDI 学习或易于识别的 CC64/66/67 映射、物理参数说明、状态仪表（只显示锁自由统计量/非 RT 快照）。
6. 验证窗口打开/关闭、UI 缩放、参数快速拖动、宿主自动化和 MIDI 并发不会阻塞音频线程。
7. 保留 `dry / radiation / optional room` 的输出对照，方便专业测评。

## 实际测试与复现

- GUI 交互、参数扫频、极端值、随机自动化、快速开关 editor；检查 processBlock allocation/locks 是否为 0。
- 宿主项目保存/关闭/重开、预设存取、跨采样率恢复，比较核心音色特征；演奏过程中切换结构状态需有明确规则。
- `pluginval` 或自建测试宿主至少运行基础加载/状态/GUI 测试；没有真实宿主写 NOT RUN。
- CI/CMake/CTest 重跑 P02–P07 的声学回归，不允许界面改动破坏声音。

## 交付文件

原创 GUI、参数/自动化/预设、状态迁移、编辑器稳定性报告与 `experiments/P09/PHASE_REPORT.md`。

## 质量门 / 不允许的捷径

通过：UI 不阻塞 DSP，宿主状态正确往返，参数调整可重现且错误预设不造成崩溃。
